# v1.0: tested on the real backend, waits that feel natural, a class's time from the app

**Date:** 21 Nov 2026

[v0.9.1](v0.9.1.md) was the version for class. Before the teacher and the first students start, it was tested on the
studio's real backend, Google's Apps Script server over the Sheet, with test accounts: requests sent at once, slow
answers, lost connections, a student in another time zone. What it found changed how the app waits, three fresh
reviews read the code, and the teacher can now move a class from the app. v1.0 is the version the teacher and the
first students use in class from late November.

## For the studio

### Waits that feel natural ([decision 22](../decisions.md))

On the real backend a write took 5 to 10 s, and the after-class Done button stayed grey for 17 to 19 s with nothing
to show for it. Dhwani asked that the wait feel natural.

- The app opens on what the student saw last, kept on the phone for that sign-in and language, with a thin line at
  the top while it reads afresh.
- Out of reach, a calm line says "Couldn't reach the studio. Showing what you saw at 4:51 PM", with Try again.
- The answers after class and a practice on one's own are saved on the phone at once and sent in the background, one
  at a time for each class or practice, in order. The student goes on at once. A check-in already worked this way.
- Until it lands, its card says "Not sent yet: it will go when you're online." What waits is sent as the app starts,
  as it comes back, and every two minutes.
- A practice keeps the time it was done (the phone's, within three days), and the server keeps its request id in its
  row, so one sent again days later is written once.
- When the server fails eight times over, the practice waits on the Practice tab with "Send again". One the studio
  refuses says why, with "Open it again", which keeps its length and its day, or "Let it go".
- Signing in, and a first open with nothing kept, show a breathing circle ("Breathe in…", "Breathe out…") and, after
  a while, "The studio's server is slow right now. Still working…"
- A write the screen still waits for (a shared note, the teacher's feedback, a placement) shows "Saving…" on the
  button tapped, and the rest of the screen stays usable.

### A class's time from the app ([decision 23](../decisions.md))

- On the teacher's class card, Change time: the start (India time, 24-hour), the length from 10 to 180 minutes, and an
  "In 5 minutes" button. Today's classes already over are listed under "Earlier today", to give one a later time that
  day.
- Refused, with the reason in the sheet: a time already passed ("Times are 24-hour: 6:30 PM is 18:30"), an overlap with
  another class of the batch, and a class students have already said how it went. Check-ins made before it move with
  it.
- The batch's time no longer moves a class the teacher set; its card says "time set by you". The batch's regular time
  stays in the Sheet.
- A 10-minute class opens the after-class questions as it starts, so a class can be tried at any hour.

### Reset the studio

The Sheet has its own menu: Satt Chitt Anand → Remove test people…, Reset the studio… and New group code…. Remove test
people deletes everyone whose name starts with TEST, and their rows. Reset the studio, after RESET is typed, removes
everyone and every row they made, and puts back what the teacher set: the batches' and classes' Meet links, each
class's curriculum, and each class's time. The batches, the curriculum, the settings and the Dashboard stay, and the
teacher code works again.

### Smaller changes

- A student abroad sees the days and times on their own calendar, with India's time beside them.
- Signing in shows an error only once a call has failed, and a retry after a lost answer gets the first answer
  instead of "number taken".
- Once a waiting student has sent their answers about themselves, the card offers to change or add to them.

## Tested on the real backend

With Dhwani's approval, a test teacher and test students (names starting TEST, numbers that cannot be real) used the
live backend on 20 and 21 November. Reset the studio clears them before the field test.

- **Requests at once.** Six sign-ups sent at once, with a second copy of one number: 8 of 8 checks passed. Each got
  an account and an id of its own, the doubled number one account, and a sign-up sent again its first answer. With
  twelve at once, four were told the server was busy, which the app's retry handles.
- **No mix-ups.** No answer went to the wrong person, and every write sent again with its request id was written
  once. The Insights tab and the class reviews add up to the Sheet's rows.
- **Slow answers.** Check-ins from four students at once took 5.5 to 10.3 s, and answers after class 5.5 to 10.8 s.
  On a busy laptop the old after-class Done waited 17 to 19 s, and a cold start said "Connecting…" for 10 to 13 s.
  This led to the waits above.
- **Shorter locks.** What a class sends together now holds the Sheet's lock only for the tabs it writes. A practice's
  time under the lock fell from about 3.0 s to about 1.9 s, and ten practices sent at once met no busy answer; the
  slowest took 22.5 s.
- **After the last backend was deployed.** The teacher moved a class to start in three minutes, 10 minutes long; a
  student saw the new time, checked in, and answered after class as it started. A class with answers kept its time.
  A practice ended two hours earlier kept its time, and sent again 10.5 minutes later with the same request id, it was
  written once. The Sheet added its two new columns by itself. 14 of 15 checks passed; the other expected a different
  error code for a length under 10 minutes, which the server refused as it should.

## Three fresh reviews

Each review read the code with no stake in it. Each finding was fixed, with a test where one fits.

- **The new waits.** A practice sent again after the server's ten-minute memory of a request was gone could be
  written twice; the request id now lives in the practice's row. A practice sent late took the day it arrived; it
  now keeps the phone's time. Two sends for one class could land in the wrong order; they now go one at a time. An
  answer that had landed could show again as not told; it stays shown until its window closes. A refused practice
  reopened without saying why; it now waits on the Practice tab with the reason.
- **The fixes and Change time.** No blockers. At a cold start, what waited was held until the two-minute loop; it is
  now sent at once. A practice opened again took a new length and day; it keeps the first, and "Send again" resends
  it with the same request id. A class could be moved into the past; the app and the server refuse it. Change time
  now takes Devanagari digits.
- **The last fixes.** Clean, with two optional points (Open, below).

The backend went from 122 to 228 tests, and the app's JVM tests from 41 to 85.

## The release

- versionName 1.0, versionCode 6, signed with the same key as v0.9.1, so it installs over it as an update. The APK is
  on the [v1.0 release page](https://github.com/DhwaniMundra/satt_chitt_anand_yoga/releases/tag/v1.0).
- The backend: paste the new `Code.gs`, Save, and deploy a new version of the same deployment
  ([steps](../../appsscript/README.md#update-later)). No `setup` run is needed: the Sheet's two new columns,
  `request_id` in `solo_sessions` and `time_set_by` in `class_sessions`, add their headers the first time a value is
  written to them. The app of v0.9.1 works with this backend as it is.
