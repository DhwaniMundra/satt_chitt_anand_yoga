# v0.9.1: without WhatsApp, attendance without a check-in, the streak in classes

**Date:** 20 Nov 2026

[v0.9](v0.9.md) went out for testing as a practice tracker. Then the studio asked that the app work fully without
WhatsApp, two decisions about attendance were looked at again, an independent review read the code, and a fuller
two-phone test ran the whole loop on phones without WhatsApp. v0.9.1 is the result, and the version the teacher and
the first students use in class from late November.

## For the studio

### Works without WhatsApp ([decision 19](../decisions.md))

The studio asked for this: a student may not use WhatsApp, and a class may keep in touch elsewhere.

- Sign-up asks for a phone number, with a hint for a number from outside India. The account was always the phone
  number.
- Every share goes through Android's share sheet: a class's link, the invite with the group code, a new password.
  WhatsApp is one choice there.
- The class group's link is optional and may be any link. The two-phone test sets a Telegram group's link, then
  clears it.
- The messages are plain text, without WhatsApp's `*bold*`, so they read the same in an SMS or an e-mail. Once the
  owner sets `app_link` in the Sheet's settings, the invite says where to get the app.
- No screen in the flow names WhatsApp, in English, Hindi or Marathi. The Ask tab's notes say that links and codes
  come from the teacher, however the class keeps in touch.

### Attendance without a check-in ([decision 20](../decisions.md))

The class's message carries the Meet link, so many students join from it and open the app only afterwards. In v0.9
their class and their answers were lost.

- After class, a student of the class's batch who did not check in is asked "Were you in class?" and can say how it
  went. That records that they came, with no mood before.
- Such a class counts as joined and in the streak, but makes no before-and-after pair, so the mood lift still comes
  from pairs only.
- Check-in is offered from an hour before class whether or not the class has a link. Join opens the call at once, and
  the check-in goes in the background.
- A check-in is kept on the phone until the server has it, and sent again whenever the app starts or comes back. The
  two-phone test checks in with the server out of reach and sees it land once, when the server is back.

### The streak counted in classes ([decision 21](../decisions.md))

Batches do not meet every day. Counted in calendar days, a Mon, Wed, Fri student never had a streak above 1, and
everyone had 0 on Monday.

- The streak is now "Classes in a row": the classes of the student's batch, at the time of each, that they came to.
- A class still to come or under way does not break it, nor one nobody came to (it was probably not held).
- After a move, each class counts in the batch the student was in at its time, so a move neither breaks nor restarts
  the run.

## Two reviews

An independent review read the code after the v0.9 release, and a second review followed the first round of fixes.
Each finding was fixed, with a test where one fits; the second reviewer's own checks became backend tests. The
backend went from 92 to 122 tests, and the app gained JVM tests for the server's JSON, its error codes, text limits and
the practice on one's own.

- **The Sheet as people type in it.** A time of day typed in the batches tab was read eight minutes late (07:00 as
  07:08). Times now read as typed: 07:00, a number Sheets kept (7.15 for 07:15), "5:30 pm", "7 am", the hour alone and
  Devanagari digits. `setup()` makes the column plain text. A dose typed as words ("5 breaths") counts by its number,
  one of 2.5 shows as written, and an odd row no longer stops a screen.
- **One class per batch per day.** When the owner changes a batch's time, its coming class moves in its own row,
  keeping its id, its own Meet link and its curriculum, and the day gets no second class. A class moves only while
  nobody has checked in and both its old and its new start are more than an hour away.
- **Whose class it is.** One rule decides the check-in, the after-class questions and the streak: a class is a
  student's when they were in its batch at some moment while it ran, whether the teacher placed them from the app or
  the owner set the batch by hand in the Sheet.
- **Links as people paste them.** Meet with a query or capitals, g.co/meet, Zoom (keeping its password), Teams and
  Jitsi; words around a link are skipped. Each link field saves on its own, and a refused one says why beside it.
- **Writes sent once.** A write that creates something carries a request id, and a repeat within ten minutes gets the
  first answer. Only such writes are retried by themselves; sign-in, sign-up, reads and password changes never are. A
  practice sent again after an unknown outcome keeps the length it was first sent with.
- **Kept when the phone turns.** The answers after class, the intake's pain areas and poses, and the link fields
  survive rotation; a practice on one's own survives Android closing the app.
- **Asking first.** Remove and New code ask before acting. The new-password dialog stays until OK, with Copy and
  Share, and a student can change their own password on the Me tab.
- **Text in Devanagari.** The limits on each field are set for Hindi and Marathi and counted in code points, with a
  count near the limit.
- **Small things.** "+91 0…" is the same number as "0…", and a deleted student in a class review is "A former student".

## The two-phone test

[`two_phones_v0.9`](../evals/two_phones_v0.9.md) ran the whole loop on v0.9, on two phones without WhatsApp. Its one
failure: a moved student never sees the teacher's note on the move. That note belongs to the teacher's review history,
so the check now looks for it in the Sheet's `batch_changes` tab; the app has no screen for it.

For v0.9.1 the test added what changed: a link refused beside its own box while the others save, a Meet link pasted
with `?authuser=0`, a Telegram group link set and cleared, "Were you in class?", answers kept when the phone turns,
Remove and New code asking first, a password changed on the Me tab, "Classes in a row", the owner moving a batch's
time in the Sheet, a check-in made while the server is out of reach, and both Today tabs in Hindi.

| Run | Build | Passed | What it found |
|---|---|---|---|
| v0.9 | debug, release | 86 of 87, 85 of 86 | The note on a move, above |
| v0.9.1, first | debug, release | 122 of 124, 121 of 123 | A student placed after a class was asked whether she was in it; a class card's Save stayed on after its link was saved in another form than typed. Both fixed |
| v0.9.1, with the Sheet's hand edits and a check-in offline | release | 130 of 130 | |
| v0.9.1, last | release | 131 of 131 | Adds a dose of 2.5 typed in the Sheet ([report](../evals/two_phones_v0.9.1.md)) |

The last run tested the code before two later fixes, each with a test: a batch set by hand in the users tab is the
student's from then on, and a practice sent again keeps its length (above).

The Ask tab is not part of this test, as Gemma needs a phone with 6 GB; the companion's evaluation is v0.9's
([`companion_v0.9_phone`](../evals/companion_v0.9_phone.md)).
